# Инструкция по запуску RustOS

## 🎯 Быстрый старт

```bash
# 1. Собрать ядро
./build.sh

# 2. Запустить (автоматически создаст FAT32 диск)
./run.sh
```

### 📺 Режимы запуска

**Графический режим** (для работы с shell):
```bash
./run.sh
```
- ✅ Открывает окно QEMU с VGA выводом
- ✅ Полноценный интерактивный shell
- ✅ Можно писать команды и работать с файлами
- 🚪 Выход: `Ctrl+A`, затем `X`

**Режим отладки** (serial output в терминал):
```bash
./test.sh
```
- 🔍 Вывод идет прямо в терминал (можно копировать)
- 🔍 Показывает все `serial_println!` диагностические сообщения
- 🔍 Используется для отладки (видно IRQ, ATA операции, etc.)
- 🚪 Выход: `Ctrl+C`

## ✅ Что происходит при запуске

1. **build.sh** собирает ядро → `rustos.bin`
2. **run.sh** проверяет/создает `disk.img` (100MB FAT32)
3. QEMU запускается с правильной конфигурацией:
   - Загрузка с floppy (`-fda rustos.bin`)
   - FAT32 диск на IDE Primary Master (`disk.img`)
4. RustOS загружается и **автоматически монтирует FAT32**

## 💾 Persistent Storage

После успешной загрузки вы увидите:

```
✓ FAT32 filesystem mounted successfully!
  Files and command history will persist across reboots.
```

Теперь все файлы сохраняются между перезагрузками:

```bash
> pwd
/
> mkdir data
> cd data
> write test.txt "Hello, World!"
> cat test.txt
Hello, World!
> reboot

# После перезагрузки:
> ls
/ (2 items):
  data - <DIR>
  .history - 42 bytes
> cd data
> cat test.txt
Hello, World!
```

## 🐛 Если возникает Double Fault

### Проверьте конфигурацию QEMU

**❌ НЕПРАВИЛЬНО** (только один диск):
```bash
qemu-system-x86_64 -drive format=raw,file=rustos.bin
```
Проблема: Нет второго диска для FAT32!

**✅ ПРАВИЛЬНО** (через run.sh):
```bash
qemu-system-x86_64 \
    -drive format=raw,file=rustos.bin,if=ide,index=0 \
    -drive format=raw,file=disk.img,if=ide,index=1 \
    -serial stdio
```

- `index=0` = Primary Master = загрузочный диск
- `index=1` = Primary Slave = FAT32 (драйвер читает отсюда!)

### Запуск без disk.img (только RAM disk)

Если хотите запуститься БЕЗ persistent storage:

```bash
qemu-system-x86_64 -drive format=raw,file=rustos.bin,if=ide,index=0 -serial stdio
```

Вы увидите:
```
⚠ Could not mount FAT32: No ATA drive detected
  Using RAM disk (data will be lost on reboot).
```

Это нормально - система работает, но данные не сохраняются (нет второго диска).

## 📋 Отладка

### Вариант 1: QEMU debug режим

```bash
qemu-system-x86_64 \
    -fda rustos.bin \
    -drive format=raw,file=disk.img,if=ide,index=0 \
    -serial stdio \
    -d int \
    -no-shutdown \
    -no-reboot
```

- `-d int` - показывает interrupts/exceptions
- `-no-shutdown` - не выключается после ошибки
- `-no-reboot` - не перезагружается после triple fault

### Вариант 2: Проверка disk.img

```bash
# Проверить тип файловой системы
file disk.img
# Должно быть: "disk.img: DOS/MBR boot sector, code offset 0x0+2,
#               Media descriptor 0xf8, sectors/track 32, ..."

# Примонтировать и проверить содержимое (Linux)
sudo mkdir -p /mnt/rustos
sudo mount -o loop disk.img /mnt/rustos
ls -la /mnt/rustos
sudo umount /mnt/rustos
```

## 🔧 Пересоздание disk.img

Если disk.img поврежден:

```bash
rm disk.img
./run.sh  # Автоматически создаст новый
```

## 📖 Архитектура

```
IDE Primary Bus (0x1F0 порты)
│
├─ Primary Master (0xA0) ┌─────────────────┐
│                        │  rustos.bin     │ ← Загрузочный диск
│                        │  (bootloader +  │   QEMU загружается отсюда
│                        │   kernel)       │
│                        └─────────────────┘
│
└─ Primary Slave (0xB0)  ┌─────────────────┐
                         │  disk.img       │ ← FAT32 persistent storage
                         │  (100MB FAT32)  │   ATA драйвер читает ОТСЮДА
                         │                 │   (не с Master!)
                         │  ├─ .history    │
                         │  ├─ data/       │
                         │  └─ ...         │
                         └─────────────────┘
```

**ВАЖНО:** ATA драйвер настроен на чтение **Primary Slave** (0xB0), а не Master (0xA0), потому что Master используется для загрузки!

## ⚙️ Важные детали ATA драйвера

Исправлены критические таймауты согласно OSDev Wiki:

1. **После выбора диска**: 15 чтений статуса (~420ns)
2. **После передачи данных**: 15 чтений статуса (сброс DRQ)
3. **Floating bus detection**: проверка статуса = 0xFF
4. **IDENTIFY команда**: определение наличия диска

Эти исправления устраняют Double Fault при загрузке.
